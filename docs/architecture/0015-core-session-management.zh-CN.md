## 六项能力的实现范围

| 能力 | Codex + Copilot | Copilot CLI / 网关 | Antigravity 1.4.4 / 网关 |
|---|---|---|---|
| 重命名 | 沿用原生协议与持久化 | 支持执行中改名，后续回复保存不覆盖标题 | 同左 |
| 归档、恢复 | 沿用原生协议 | 归档先取消并等待执行真正结束，再持久化；恢复不重放消息 | 同左 |

| 聊天分支 | 复用原生 `thread/fork`，保留 provider、模型、推理与权限 | 使用 SDK 的真实持久上下文克隆，支持已记录事件边界的指定轮次 | 有上下文的独立分支明确拒绝；不复制 session ID 或伪造展示历史 |
| 项目归属 | 沿用原生项目路径 | 协议 `projectId` 的 null/空字符串清除已验证；原生侧栏 membership 由宿主既有服务管理，另行验收 | 同左 |

| 查找、重新打开 | 原生侧栏、搜索、历史与恢复 | 合并标题/预览搜索，恢复原 CLI session 并续聊 | 同左 |

表中归档、恢复、永久删除属于同一核心能力。没有新增会话页面、独立侧栏、管理 HTTP 服务或第二套数据库。

## 写入所有权

`ThreadStore.saveExecution()` 只提交执行字段：CLI session ID、turns、运行状态、更新时间和首条消息预览。标题、项目、模型、推理、审批、归档及置顶始终来自最新持久文档；旧执行快照不能覆盖 UI 意图。该边界对未来新增元数据同样成立，无需逐字段补一串合并条件。

设置请求继续在目录异步读取后重读最新记录并原子保存。删除/归档/分支有按聊天的操作占用；占用期间拒绝竞争的新 turn。归档、删除的取消信号不等于执行已完成，需等待 run 真正结束。取消未在 30 秒内结束则明确失败，保留聊天，不假报操作成功。

原生入口的 `thread/fork` 也经过已有会话归属控制器：CLI 使用自己的模型、推理和工具审批，不能误带宿主 Codex 的 OS 沙箱设置。原生 provider 请求保持原生权限语义；模型切换待保存期间也不能分支到旧模型。

## 删除与故障恢复

永久删除用同一个聊天 JSON 的原子替换，将本地内容变成最小 tombstone。tombstone 只保留 ID、engine/adapter、删除时间和清理状态，不保留标题、消息或工具内容。归属记录保留是为了让旧请求继续被网关明确拒绝，不能因为记录消失而回落到原生模型。签名分页 cursor 的旧尾页也会过滤已删除条目。

底层 CLI 清理在本地删除提交后执行。Copilot 使用官方 SDK `deleteSession`，不操作项目目录；清理确认后连待清理的 CLI ID/cwd 也移除。若底层清理未确认，请求返回“已在本地删除、CLI 清理待确认”的错误；本地聊天不会重现，再次删除可在重启后继续清理。若本地提交失败，则完全不调用 CLI 删除。关闭网关会等待已进入的删除/分支/归档操作。

Antigravity 1.4.4 的隔离调用确认 `session/delete` 为 Method not found。本轮只承诺永久删除 MyCodex 本地记录；不宣称删除其独立账号存档，也不通过猜测私有目录结构来删除文件。

## 分支的上下文语义

Copilot SDK 1.0.28 / CLI 1.0.105 提供 `rpc.sessions.fork({sessionId,toEventId})`，其中事件边界是排他的。新 turn 在接收到实际根 `user.message` 事件后记录私有事件 ID。`beforeTurnId` 直接使用该 turn 的起始事件；`lastTurnId` 使用下一 turn 的起始事件；最新完成上下文无需截断。分支取得新 CLI session ID，历史前缀复制仅用于展示；后续推理上下文由 CLI 自己的 fork 提供，不重放任何消息或工具。

分支记录使用 `forkedFromId`，不设置 spawned 子代理的 `parentThreadId`；删除来源不会递归删除网关的独立分支。来源正在执行时明确要求先停止，避免在不确定边界克隆。分支持久化失败时只清理新克隆，不清理来源。

聊天分支共享原工作目录，隔离的是会话上下文；没有复制 worktree。迁移前未记录事件边界的老 CLI 聊天可以从当前最新上下文分支；不能可靠定位的历史中间轮次会拒绝，不能静默改成整个聊天。空聊天可独立新建空分支。Antigravity 的初始化只声明 resume/list 等能力，隔离 `session/fork` 返回空对象而没有新 session ID，因此有上下文的分支目前不可用；没有升级运行时或绕过其协议去复制私有存档。

Codex + Copilot 的分支复用原生 core，限定模型 ID 由 router 转回原始 ID，provider 注册和目录路径保留。已知原生快照的模型、推理、审批、命名权限 profile 和工作区根也带入分支；复杂权限不能降格为较宽默认值。没有重新实现 native 历史或复制 CLI session ID。

固定 core 0.165.0-alpha.1.2 对仍被分支引用的原生来源报 `forked history still references it`。本轮保留此保护：可归档来源，分支可独立续聊；不承诺强制删除这个来源，也不通过修改 rollout 绕过限制。删除分支后可再删除来源。

## 侧栏与搜索

本机 `ThreadMetadataUpdateParams` 不需要新增 `isPinned`。静态核查已验证官方主进程的 pinned service、`PINNED_THREAD_IDS` 与 `thread/section/move` 链路；内置置顶分组 ID 为 `01984de2-8f74-7c91-a3b2-5c5e937cf318`。网关保存 section、进入时间及其 CLI 顺序，原生服务仍负责侧栏持久化和用户交互。只接通置顶/取消置顶，不扩展自定义分组或跨原生/CLI 的交错排序。

`thread/search` 返回当前安装协议要求的 `{thread,snippet}` 条目；router 按时间合并原生/CLI 命中，保留分页和引擎限定标识。CLI 只搜索标题/预览，不实现消息全文搜索。已有查找、恢复不依赖模型目录可用。

本机 CLI 对 `modelProviders:null` 使用默认 provider，对 `[]` 才列全部 provider。配置了原生 provider 时，router 将侧栏无筛选的原生历史查询规范为 `[]`，否则原生 Codex + Copilot 历史及置顶会被漏掉；用户显式筛选仍保留。普通原生 resume 不重新注入 provider/config，否则会将已有模型/推理覆盖成进程默认值；其持久配置继续由 core 恢复。

## 原窗口置顶缺陷与修复

专门测试聊天 `MYCODEX-MGMT-COPILOT-1031` 使用 Copilot CLI 的 `gpt-6.1-sol`，发送与原生改名已获用户确认。置顶请求也确实写入网关的内置 pin section，但官方 App 工具返回的置顶列表中没有它。

静态追踪当前已验证宿主的 pin service 发现，它使用 `thread/list` 的 `sortKey: "section_position"`、空 provider 筛选、内置 section ID 及 `useStateDbOnly: true` 查询。安装 CLI 的 `ThreadSortKey` 也包含该值；原网关只接受三个时间排序值，导致查询失败。router 的可选目录回退随后仅返回原生结果，CLI 已保存的置顶状态便无法进入侧栏列表。先前测试只查询 section ID，未覆盖真实宿主使用的排序参数；后台通过不能代表此链路已验收。

新增两个隔离行为测试，分别复现排序拒绝和 CLI 置顶被合并列表漏掉；修复前 41 项中两项失败。源码仅补齐 `thread/list` 的安装协议排序值，`thread/search` 保持自己的枚举，不改原生置顶服务、页面菜单或持久化所有者。174 项完整 DIY 定向回归通过，包括真实安装 core 的 section-position 查询；无需重新发消息或改名。

收尾还发现工具运行时目录已在期间更新：旧网关和 helper 的 PID、启动时间未变，但其 Node 可执行文件路径移入 `codex-primary-runtime.previous`，因此严格身份比较为不匹配，不能据此称为进程已退出。没有改写回执或放宽校验。协调手动退出后，应等待约 75 秒让旧网关自然结束，再从原 MyCodex 图标启动并重新核对代次。本次修复没有主动重启、终止当前客户端或会话。

## 运行时路径迁移后的启动等待

用户反馈启动器出现 `Gateway socket ownership is uncertain; it was not removed.`。此前已观察到 Node 的运行路径移入 `.previous`：PID 与启动时间不变，但精确可执行文件身份不再匹配。旧逻辑保留 socket 的行为正确，却没有把这个情形交给启动入口已有的有限等待流程；用户可能在旧服务退出前遭遇直接报错。当前现场已恢复为新的、严格匹配的客户端/网关/helper，未对生产进程执行终止或修补回执。

`appServerGatewayBackend.stage()` 现对同一私有配置、同 PID 与启动时间、但可执行文件路径发生变化的情形返回 `GATEWAY_RUNTIME_RETIRING`，由现有启动入口最多等待 75 秒。这个较窄判断仅授权等待，不授权复用、终止进程或删除仍占用的 socket。启动时间不同仍维持明确拒绝；旧进程结束后，仍由原有身份、私有目录和 socket 类型门禁决定是否回收残留。

两个 Mac 宿主版本的隔离 backend 测试均先复现失败，再验证等待与拒绝两条行为：回执保持、活 socket 保留、不同出生身份不放行。174 项完整 DIY 回归通过；不运行跨平台发行，不放宽 Desktop 版本/摘要或完整进程身份检查。
