# 宿主升级：后端启动与页面适配分离

2026-11-02。本轮只处理 Mac 本机接入。源码和隔离验证完成；当前客户端没有重启、重配或加载这次修复，原窗口验收留待统一重启后进行。

## 已确认的原因

官方客户端升级至 `26.1027.51404`，内置 CLI 从 `0.165.0-alpha.1.2` 升至 `0.166.0-alpha.5.1`。原入口把页面版本、ASAR 哈希和 CLI 哈希作为一个整体开关。页面契约不匹配时进入保护启动，该进程使用 `engines: []` 的离线连接，而非用户配置的网关连接。恢复旧会话因而在调用模型之前报 `Codex + Copilot is not configured for this instance`。这条错误不能归因于额度耗尽或历史丢失。

页面同时有真实变化，不能只更新资源路径：旧管理器导出 `VUn` 在新版指向模块初始化函数，旧消息总线导出 `eLt` 指向请求 schema。新版的管理器为 `sYn`，消息总线单例为 `zRt`。主进程也从 `main-*.js` 改为 `early-bootstrap` 分块；置顶查询的语义仍为 `section_position`，引号形式改变。

## 职责与行为

| 边界 | 所有者 | 验证与失败行为 |
| --- | --- | --- |
| 官方应用身份 | `bridge/desktop-host-capabilities.mts` | 校验原应用的签名、bundle ID、Team ID 和可执行文件。身份不可信时拒绝启动。 |
| 原生协议兼容 | 同上 | 在隔离 HOME/CODEX_HOME 导出实际 CLI schema，检查已消费的字段和新增必填参数；不登录、不推理。每个进程按二进制哈希缓存检查结果。 |
| Provider 与 CLI 网关 | `bridge/desktop-backends/app-server-gateway.mjs` | 协议通过后沿用配置的引擎、Provider 参数和网关。未知页面版本不再删除这些能力。 |
| 页面适配 | `bridge/desktop-current-host-contract.mjs`、`bridge/desktop-native-composer.mts` | 保留版本/ASAR/CLI 的精确 UI 元组，并按版本声明导出名；挂钩前检查管理器和总线的方法。错误语义绑定在修改原型之前被拒绝。 |
| 原窗口启动 | `bridge/desktop-current-host.mjs`、`bridge/desktop-shortcut.mjs` | 分别报告 backendState、uiState。未知页面不启用 CDP 或页面 helper；页面就绪失败、helper 启动失败或后续退出均不停止已就绪后端。 |
| 真正不可用的后端 | `bridge/desktop-protected-start.mts` | 仅在原生协议不兼容或后端准备失败时保留离线保护；记录具体原因到私有 status.json。CLI 历史不退回原生 OpenAI 推理。 |

没有新增常驻服务、代理模型或第二套会话数据库。原审批策略、引擎归属、历史和配置继续由原有 Provider、router 和 gateway 管理。没有迁移或重写真实会话，也没有修改官方应用文件或原生 config.toml。

页面处于 unsupported/unavailable 时，已配置的原生 Provider 路径可独立恢复 Codex + Copilot 历史；CLI 网关本身也可用。但第三方 CLI 的新建、模型选择及部分页面入口依赖页面适配，不能把“后端 ready”理解为所有 UI 功能均可用。helper 已启动只表示 starting；原窗口实际安装和交互需要另外验收。

协议字段检查是启动前的保守检查，不是对未来协议语义的完整证明。协议真正变化仍可能需要修复；本次消除了“仅页面升级就撤掉全部后端”的失败传播，不承诺任意未来版本免适配。

## 统一重启后的验收清单

当前进程仍使用原先的离线保护连接；仅改源码或刷新模型目录不能替换它已启动的 Provider 参数。本轮遵守“不重启”要求，没有改写这个运行中连接，也没有启动 helper。

后续在用户确认可以退出时，使用现有 MyCodex 入口重新准备并启动原应用，沿用原 profile，先检查正常网关连接和 Provider 已注入，再在原窗口验收：

1. 从侧栏打开“开发会话”，确认 Codex + Copilot / Sol 标识、历史、原推理与权限；发送受限测试消息并验证上下文。
2. 原生新建页查看全部引擎；选择第三方模型、调整推理，确认没有“无法更新模型设置”。
3. 分别验证 Copilot CLI 和 Antigravity 已有会话同引擎模型切换，推理和审批保持；不跨引擎改写既有历史。
4. 用专门的测试聊天验证侧栏找回、重命名、置顶、归档/取消归档、选定轮次分支和删除，保全工作聊天。
5. 再次正常退出和启动，复核历史、归属、模型与设置。核查 helper 的安装成功日志，不能只以进程存在判定 UI 成功。

这不是已发布安装包。VERSION、native core、共享开发文档和其他任务现场保持；没有提交、推送或运行 Windows/六平台构建。

## 重启后新建页报错：补上延迟初始化的绑定状态

用户重启后在新建页调整 Antigravity 推理强度，仍出现“无法更新模型设置”。本次真实窗口验收失败，前面的启动链、模型推理和即时就绪的浏览器 fixture 通过不能替代它。

只读日志确认新的应用 PID 为 34420，正常网关 PID 为 34377，配置中的三个引擎仍在；页面 helper 34487 已退出，最后错误为 `Native page capabilities differ from the verified adapter`。原应用日志进一步确认失败的 `config/batchWrite` 返回 -32602，错误为 `Third-party model preferences cannot be written into native Codex configuration`。页面挂钩未安装，原生新建设置写入因此被已有路由保护拒绝；没有移除该保护或允许第三方默认模型写入原生配置。

静态核查安装资源，管理器 `Fmn` 与总线 `Vg` 均在声明导出后，由各自惰性初始化函数再赋值。原接口校验把“导出存在但值仍为 undefined”与“接口语义错误”合并成永久失败，helper 没有机会等到页面自然初始化。旧日志没有记录具体失败字段，因此不能据此断言当时究竟是哪一个导出未就绪；这是根据安装代码定位并独立复现的明确时序缺口，仍需修复后的原窗口验证闭环。

修复只涉及原有页面适配器：声明存在、值尚未初始化时返回 pending，不访问 DOM、不安装原型挂钩、不发出网关请求。序列化安装器清理本轮监听并返回 pending，现有 watcher 正常继续轮询。等宿主自行初始化后，下一轮通过 ESM 的实时导出绑定读取就绪值并安装。没有主动调用宿主内部初始化函数，也没有增加全局拦截或常驻服务。缺失导出、已初始化但接口错误的情况仍拒绝，并记录不含聊天内容的具体接口检查结果。

新增单元回归先复现旧代码永久失败；独立 Chrome 中使用真正的 ESM `export let` 模拟总线与管理器先后初始化，验证等待阶段无 DOM/原型/RPC 变动，之后无需重载页面绑定、无重复目录请求，并正确响应 Antigravity/high 的草稿设置，原生配置写入为零。三个版本各 36 项浏览器检查、225/225 完整回归、类型/构建/模块检查通过。

当前客户端和网关没有重启；没有启动新 helper 或操作真实窗口。Computer Use 明确拒绝操作 `com.openai.codex`，没有改用其他通道操作或读取该窗口。源码修复已编译并准备，但原窗口尚未加载，需用户通过正常 MyCodex 入口重新加载后确认设置结果。提示体验优化继续等待当前兼容验收。见 [延迟初始化修复记录](evidence/2026-11-02-lazy-native-exports.json)。
