# 独立于页面的兼容状态提示

2026-11-02。MyCodex 的 Mac 启动入口已更新。后续已实际验收菜单和原生提示链路，生产页面健康报告仍待下一次自然重开加载，见 [ADR 0024](0024-upgrade-continuity-acceptance.zh-CN.md)。没有为测试主动断开生产网关或页面绑定。

## 体验与所有者

`desktop-launcher-macos.swift` 继续打开原来的官方应用，同时保留一个 MyCodex 菜单栏入口。正常接入不弹窗；已确认的故障按功能提醒一次。等待初始化、状态未确认和有更新待加载只更新菜单栏；稳定恢复后也只短暂更新菜单栏。重检、重开图标或重启菜单栏入口不会重复弹出同一未恢复问题；任何时候都能主动查看状态。具体去重和分级见 [ADR 0025](0025-nonintrusive-status-notices.zh-CN.md)。

提示包括后端路由和页面自定义控件两部分、受影响能力、检查时间及处理建议。页面失败时后端仍可显示就绪。后端状态检查是本地路由接入检查，不保证模型账号登录、额度或推理可用；页面状态检查是挂载检查，不声称所有交互都已验收。第一版没有逐个隔离全部 DIY 子组件。

“稍后查看”只关闭说明窗，菜单栏状态仍在；“退出状态提示”只退出本次启动器及它自己的只读监测子进程，不关闭 ChatGPT、网关或工作会话。没有登录项、系统通知权限申请或新的框架依赖。代价是一个常驻原生入口进程和一个只读 Node 监测进程。

## 状态来源

- `desktop-gateway-ui.mts` 在已有挂载循环中报告 pending、ready、retrying、unavailable。报告写入独立私有 `current-host-ui-status.json`，不改启动回执或 Provider 配置。
- `desktop-ui-health.mts` 校验应用和 helper 的进程生命周期、源码代次与报告时间。新鲜的报告才可显示 ready；状态超过 45 秒过期、初始化持续超过 45 秒、helper 退出或来源不匹配均不能显示正常。旧 helper 不得覆盖新应用生命周期的报告。报告失败不会阻断页面挂载或后端。
- `desktop-shortcut.mjs` 的只读检查分别返回 backendState、uiState、uiReason。进程存活不再被当成页面接入成功；旧版 helper 未上报时明确显示“未上报”，不伪造 ready，也不据此移除后端。
- `desktop-status.mts` 每 15 秒重新检查进程、网关连接和页面报告。应用文件元数据变化会使宿主缓存失效，再执行签名与实际原生协议检查；安装未变化时复用检查结果，不每轮导出 schema。配置读取失败、监测进程退出同样会显示需关注，不静默继续显示正常。

这个链路没有 DOM 选择器、CDP 操作或模型请求。页面不兼容不会让提示本身消失。非模态状态窗不调用 `runModal`，自动提醒不激活官方应用或强制关闭工作窗口。

## 验证与加载边界

先用失败回归确认旧检查只根据活进程返回 starting，即使已提供新鲜 ready 报告也不会识别。修复后覆盖正常、初始化超时、报告过期、瞬时失败、恢复、来源变化、私有文件和符号链接保护，以及同一问题去重和经过 pending 的恢复提醒。实际原生壳使用的 CLI 参数也经过子进程验证。

当前共享工作区完整回归 237/237 通过，严格类型、生成产物和模块检查通过；Swift 编译、入口签名验证及只读 `--check` 通过。独立原生视图以明暗两种外观渲染，验证文字布局；这不是生产窗口的自动点击或弹窗验收。早期视图裁切已修复。

原窗口仍是本轮用户重启的 PID 68483；当前 helper 68542 尚未加载结构化健康报告。因此新只读检查如实返回后端 ready、页面 unreported；这不代表刚通过人工验收的页面已失效。新 helper 会在用户下次正常退出并从 MyCodex 启动时加载，无需为提示功能现在再重启。
