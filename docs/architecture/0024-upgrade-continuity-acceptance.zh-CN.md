# 升级后的模型与续聊连续性验收

2026-11-02。本轮只新增验收门禁与记录，没有更换当前客户端、网关或页面 helper。菜单栏入口及状态监测已实际运行。

## 底线与范围

页面增强不适配，不能成为移除 Provider、清空 CLI 网关、隐藏全部外部模型或将第三方聊天转给原生 OpenAI 模型的理由。升级兼容验收必须覆盖模型目录、模型选择、发送及已有聊天的冷恢复；这些失败时不得仅凭源码编译或进程存活宣告兼容完成。

原生协议真实破坏、账号登录、服务商额度和模型服务失败，不能用伪造可用状态、自动切换引擎或放宽审批来掩盖。未知私有前端和未来协议仍可能需要适配；本轮没有实现官方客户端版本回滚，也不承诺第三方服务永远无故障。

## 默认自动门禁

`tests/desktop-upgrade-continuity-test.mjs` 已纳入 `tools/typescript-task.mjs test`，随默认 `test:diy` 运行。在 Mac 上缺少实际安装的 CLI 会失败，不能跳过后声称完成该项验证。

这条测试使用实际安装的原生 CLI、实际 routed-stdio 前端和真实本地网关 IPC，配合无外部请求的合成 CLI 引擎，全程没有页面 helper、CDP 或渲染器挂钩。覆盖：

1. 页面 unsupported / unavailable 时，状态仍独立显示后端 ready。
2. 原生 `model/list` 仍收到外部模型，宿主 `config/batchWrite` 选择模型与推理成功。
3. 原生配置文件保持字节不变。
4. 创建与发送完成，重建独立 app-server 前端后恢复同一聊天。
5. 模型、推理强度、审批策略、历史与 CLI session 身份保留，第二轮在不重复提示 nonce 的条件下使用原上下文。
6. 页面恢复只产生状态恢复通知，不重建工作聊天。

这验证的是页面缺席下的协议与状态连续性，不代替未来官方页面的实际控件点选验收。已有启动器分支测试同时保护未知页面继续保留已配置后端、helper 退出不终止后端、原生配置和权限不被覆盖等边界。
