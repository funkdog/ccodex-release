# ADR 0028：共同工作记录与非代码工作接续

日期：2026-11-04（Asia/Shanghai）。状态：产品方向与伴随工作台视觉已由用户采纳；统一读写插件已添加并连接，真实小鼠头的插件 status 调用成功。新版网关已加载三个共同工作接口，插件目标和工作读取通过；真实记录写入、页面展示及完整小队接线仍待验收。

## 已采纳的产品约定

聊天与工作台围绕同一份工作：聊天承载思考、讨论与纠偏，工作台保留当前焦点、采用的依据、实际进展、下一步及需要用户判断的事项。模型按任务选择工作方法，产品不按“开发、设计、调研”等类型硬编码执行步骤。

目标登记、继续讨论、组织执行有不同门槛。规划中的目标和工作可以保留未知；能推进的工作应有预期交回、判断标准、输入边界、负责人和下一动作。澄清本身可以是有产出的工作，不要求先想清整个目标。

共同依据区分候选、已采纳、参考与前版。模型建议和用户已采纳约定分开，沉默不自动构成采纳。重要变化更新共同记录；普通进展不要求逐轮确认。

一个目标可以包含多个工作项，各工作项按需要组织专属小队和群聊。小鼠头负责目标及跨工作项判断，小队负责本项协作与交回，队员保留各自的真实会话。工作项切换不混合群聊，选中成果可带来源回到主聊，采纳后更新共同依据。

## 第一轮实现

- `gateway/spine/work-context.mts` 定义无仓库依赖的通用记录：用户原意、期望结果、当前进展、负责人、下一步、待判断事项、交回与判据、未决问题、带来源的材料/约定/成果。
- 沿用 `WorkStore` 的单写入者、私有文件、fsync/原子替换及 revision 冲突检查。通用记录使用 `<id>.general.json`，既有代码读取器按其原有 ID 规则跳过，避免回滚时把通用记录解析为 Git 绑定。两种记录共享 ID 冲突检查，不互相覆盖，不迁移或重写既有代码记录。
- `diy/work/record` 在创建时要求 `expectedRevision: 0`，更新时要求确切 revision。规划记录不需要仓库、Git SHA、代码交接契约或虚构队员；可推进状态要求交回与判据，已采纳材料需要来源引用。
- `diy/work/context` 按确切 ID 回读目标和工作记录，分别返回当前采用、候选、参考、未决问题与下一步。它不选取“当前聊天”兜底，不发消息，不触发模型。
- `diy/work/shared_list` 提供有界分页。原有 `diy/work/list` 与代码小队执行保持兼容投影，通用工作不能隐式取得代码派发权限。
- MCP 增加 `mycodex.goal_upsert`、`mycodex.shared_work_list`、`mycodex.work_record`、`mycodex.work_context`，与 UI 经过同一网关及存储写者。
- 工作面板可显示通用记录、展开成果与依据、按 revision 采纳候选、带入讨论草稿。绑定的讨论目标存在时先定位；未绑定时动作明确为带入当前讨论，不把新聊天冒充小鼠头。采纳更新实际记录，保留下一步和未决问题。

本轮未将预览里的 Agent、小队消息、回传和角色切换改造成真实通用执行。通用工作面板明确报告尚未绑定执行入口。代码小队仍走既有专属工作树与执行契约。

## 小鼠头与已连接电脑的本机入口

官方 [Computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps) 文档说明，小鼠头在云端运行，可以在已连接电脑上创建本机 Work/Codex 任务，本机 skill 需要连接电脑。用户已确认该 Mac 的小鼠头 Computers 权限开启。上述能力说明支持这条接入路径，不能作为实际调用成功的证据；原生 CLI 的 MCP 注册也不能证明云端小鼠头自动继承了配置。

新增 `gateway/spine/work-cli.mts`，让被委派的本机执行者通过明确绑定的私有连接文件访问同一网关写者。`describe` 复用 MCP 的共同工作 schema；`status` 检查运行时实际已注册的方法；`goals` 包含尚未创建工作的目标；`list/context/goal/record` 读写既有共同记录。该入口不直接打开工作存储，不扫描其他 profile，不派发 agent，不启动模型，不重试。

本机写入额外要求稳定 ID 和明确 `expectedRevision`，成功回执包含实际保存的 ID/revision。版本冲突返回 rejected，发送前失败返回 not_sent，写入发送后连接中断返回 unknown；unknown 必须先按原 ID 查询，不能换 ID 重试。回执不等于页面已显示、用户已采纳或工作已验收。

`skills/mycodex-workbench/SKILL.md` 仅解释工作台定位、来源和接续，不按任务类型编写模型的工作方法。`tools/install-workbench-skill.mjs` 将其安装到本机技能目录，绑定当前实例的完整命令而不复制连接凭据。生成输出与 canonical 源码分开；已有无归属 skill、用户修改或额外文件使安装拒绝覆盖。不同路径中的单引号和 shell 字符按平台引用，Mac 路径通过实际 shell 调用验证。

隔离验证共新增 7 项：真实私有 IPC 登记/采纳/回读、旧版本拒写、输入预算与窄命令边界、断线不泄露配置、已提交但丢回包时不重复写入、旧网关缺能力时不写入不重启、安装归属保护与实际原生执行器的 skill 发现。新增入口验证没有模型调用。首次全套运行有一项既有 protected-start fixture 的 2 秒初始化超时；该项单独复查通过，随后全套 305 项通过，207 个模块及 481 个相对导入通过。未为此次超时修改测试阈值或无关源码。

已将生成的 skill 安装到这台 Mac，直接只读探测返回 `ready: false`，缺少 `diy/work/shared_list`、`diy/work/record`、`diy/work/context`；网关仍是原生命周期。当前工具不允许自动操作内置聊天窗口，不能用其他方式绕过这个限制或用本机 CLI 探测冒充小鼠头调用。

2026-11-04 用户交回真实小鼠头探测结果：本机任务创建返回内部错误，留下记录但没有执行回执。通过受支持的 chat 工具定位到对应任务后，确认其为 idle、零轮次；本机会话库中也没有该 ID。探测时段桌面日志有本机 executor 连接在线的样本，使用隔离 profile 比较实际原生 `exec-server --help` 直连与转发的输出及退出码一致，宿主 archive/CLI hash 与启动回执一致。这些证据不足以确认云端创建/首轮启动的内部错误根因，也不足以认定 skill 或工作台命令失败。

保留原任务，下一次只尝试按原任务 ID 续接 status，不创建重复任务、不改写连接权限或重启客户端；若仍失败，需取得原始启动错误及错误码。具体观测和边界记录在 `evidence/2026-11-04-dot-local-task-probe.json`。实际小鼠头调用和页面变化的验收仍未通过。

同日续接已成功：受支持的 chat 读取显示，该任务读取了安装后的 skill，并运行其绑定的完整 status 命令。命令返回 `outcome: not_sent` 和旧版泛化的网关不可达错误。这证明真实小鼠头的委派任务执行到了本机入口，尚未证明网关访问、记录读写或页面变化。相同命令在开发会话中可连接原生命周期的网关；不能把不同执行环境中的连接失败直接解释为服务停机。

此次修正连接诊断：CLI 在不输出 token、socket 路径和服务端原始异常的前提下，保留 `code`、`phase` 及白名单 `systemCode`，区分权限拒绝、socket 不存在、连接被拒绝、握手失败、初始化失败。真实 macOS Seatbelt 限制下，连接健康的隔离网关会返回 `GATEWAY_ACCESS_DENIED`；同一网关在限制外保持可读，且无记录写入。真实委派任务仍需运行新版诊断后才能确认其底层错误。完整门禁现为 307 项通过。

官方 [Work local security](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-local-security) 明确说明本机 shell 遵循任务的沙箱与审批设置；[Permissions](https://learn.chatgpt.com/docs/permissions) 将本地服务连接作为独立权限，并提醒不要假定 Work Cloud 支持 Codex 本机 profile。因此，本机连接授权不视为 Unix socket 访问授权，不直接套用开发会话的全权限配置。若确认权限拒绝，需在实际任务支持的权限界面或集成入口取得该连接的具体授权；不改用其他传输或直接改存储规避限制。

第三次由真实小鼠头续接同一任务时，发起方返回 `TimeoutError` / `UNKNOWN`；直接读取原任务却取得新版命令结果：`GATEWAY_ACCESS_DENIED`、`phase: connect`、`systemCode: EPERM`。命令退出码 1，未发送工作操作。随后同一轮结算为 completed，任务 idle。这确证当前执行环境的连接权限拒绝，也说明发起方等待超时不能当作子任务没有执行。最初创建内部错误及等待超时各自的根因仍未确定，不与 EPERM 合并解释。

## 工具接入：同一连接中的读写

用户明确纠正：正式工作台需要写入，读写不应拆成两条连接。采用一条“MyCodex 工作台”连接、一条隧道与同一份记录；工具分别描述其读写和执行边界，后续能力扩展沿用该连接并按需要刷新工具及授权。只读是连通性诊断的阶段范围，不是另一个产品连接。

正式接入使用 `--shared-work`，serverInfo 为 `mycodex-work`。四项读取工具与 `mycodex.goal_upsert`、`mycodex.work_record` 两项记录写入同时提供；写入实际分派前要求稳定 ID 和明确 `expectedRevision`，不是只在 schema 中声明。新建用 0，更新用当前版本，模糊结果按原 ID 查询，候选方案、用户采纳和来源的既有约定不变。代码执行、小队派发、删除和其他会话读取仍未开放，不能把“登记工作”当作执行许可。

统一入口的真实隔离子进程验收覆盖目标创建、工作创建、候选回读、有来源的采用更新、旧版本写入拒绝、重复目标拒绝、通用工作不接受代码绑定，以及派发工具不可用。所有操作经过同一网关及存储写者，未触发模型。此前只读提交确认的范围已被用户明确确认的一条读写连接替代；Platform 隧道和 ChatGPT 私有插件现已创建，后续实际接入结果见下文。

下面保留已完成的只读诊断模式，供隔离验收和明确需要只读的场景使用；正式连接不再以该模式启动。

`gateway/spine/mcp-server.mts` 增加显式 `--shared-work-read-only` 模式，serverInfo 为 `mycodex-work-read`，仅暴露：

- `mycodex.spine_status`：运行网关的健康与实际注册方法。
- `mycodex.goals_list`：目标，包括尚无工作项的目标。
- `mycodex.shared_work_list`：通用工作分页。
- `mycodex.work_context`：按确切 ID 读取同一份工作。

该模式在实际分派前拒绝写入、代码小队、原始日志、其他会话读取和任意 RPC；不能只依靠 readOnlyHint 标签隐藏写入口。未知模式或拼错的 CLI 参数拒绝启动，不回退到完整工具集。既有原生会话使用的默认完整模式保持原有工具列表。隔离子进程验收经过真实网关及 WorkService，确认能读取真实测试记录、不能更改 revision，未触发模型。

启动契约为 `node gateway/spine/mcp-server.mjs <明确的私有连接文件> --shared-work-read-only`。它是供可信本机 MCP 宿主运行的待接入服务，复用既有存储及网关；不是让受限 shell 启动后绕过 socket 权限的办法。私有网关凭据只由可信本机进程持有，MCP 调用者得到的接口限定在上述四项。

官方 [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) 提供自定义 MCP 的独立授权连接路径，可以连接私有服务而不公开公网端点。该路径现已按用户确认接入。当前没有可直接修改这条云端任务 socket 权限的工具，也没有证据证明 Codex 用户 profile 可改变其权限；原先被拒绝的 shell 路径不再重试。

正式连接和受控加载新版是两个独立门槛。两个门槛现均已通过：真实小鼠头 status 调用成功，新网关已注册三个共同工作方法。工具可达及接口就绪仍不能替代真实记录写入、采纳或工作台页面变化的验收。

### 2026-11-04 真实隧道与插件接入

## 后续验收门槛

1. 在小鼠头实际运行时证明工具可见、能读取已有工作，并从自然意图登记真实目标和通用工作。若该运行时不支持现有 MCP 接入，需要采用可验证的宿主扩展入口，不能创建一个改名的 CLI 会话代替。
2. 将已采纳的伴随布局、工作项小队群聊和队员真实会话接线；群聊、草稿、成果与状态均按工作项隔离，候选结果不自动视为验收通过。
