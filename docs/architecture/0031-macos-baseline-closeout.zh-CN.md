## 用户重开后的页面助手补修

用户交回“已重启”后，实际启动回执已绑定新源码与新配置，后端 ready；页面助手在进入 renderer 绑定前退出，错误为 `UI helper requires its matching routed gateway.`。上一轮修复只覆盖启动器，漏了页面助手中的同类代次比较，这是上一轮真实启动链验收的缺口。

启动回执的 generation 表示本次启动采用的配置；connection.json 的 generation 则属于 IPC 身份，在受控追加 CLI 引擎时保留。页面助手现在比较 `configGeneration ?? generation` 与启动配置，连接鉴权仍使用原 IPC generation。没有修改运行连接、回写旧回执或放宽任意配置／前端匹配。

补充回归先复现旧比较失败，再验证：旧配置无独立 configGeneration 时保持兼容；新配置与旧传输可以共同工作；过时配置、错误前端和空代次拒绝；真实隔离 IPC 使用原传输鉴权成功，误用新配置代次鉴权失败。完整开发门禁 342/342 通过，零跳过；76 个 TS 源码、152 个生成产物、214 个模块和 501 条导入检查通过。

还直接读取当前新客户端回执与原网关连接，调用同一个生产校验函数并完成网关鉴权，预检通过；日常配置、启动回执、连接文件及应用／网关进程寿命保持。该预检不连接 CDP，不操作窗口，不能替代页面助手实际绑定或用户界面验收。原生 UI 的工具访问限制及正式发布缺口继续有效。

补修证据见 [页面助手配置代次记录](evidence/2026-11-11-ui-helper-config-generation.json)。
