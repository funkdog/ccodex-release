# 多 CLI 精简候选版边界与验收

以下为 RC.1 的历史候选记录，不能当作 RC.2 的验证结果。当前修正见文末。

日期：2026-11-12（Asia/Shanghai）。版本：`MyCodex Adapters 0.1.0-rc.1`。来源为独立 worktree 中的已提交基线 `70e5964`，未搬入日常分支上的模型来源、跨引擎接续或 Squad 开发改动。当前没有公开发布，也没有修改旧的 `v1.2.36` 版本或安装包。

用户确认首版范围：macOS，在已有官方窗口里使用自己的 Codex、Claude、Gemini CLI 和模型。实际候选验证范围进一步限定为 Apple Silicon ARM64；原生 Codex 仍使用官方客户端的执行器，不替换成任意版本 CLI。

## 能力收敛

配置新增可选的 `gateway.workbench` 布尔值，配置向导固定写为 `false`。Desktop 解码、连接文件、routed frontend 和 Gateway 启动保持同一值。禁用时拒绝同时配置 Spine，并且不会构造 Spine、工作台、派发、雷达或日报服务；原有启用行为的默认值保持。配置变更不能通过“只追加 CLI”路径悄悄改变工作台开关。

UI 由已有无 Spine 配置的路径挂载 CLI 控件；关闭自动创建修复聊天。引擎和模型继续由既有网关拥有，审批默认 ask，取消及恢复保持原语义。本候选没有开启工作台、Squad、模型来源管理或跨引擎聊天接续。

配置向导使用独立的 `~/.mycodex/adapters/`，不覆盖已有日常配置或原 MyCodex 图标；原生图标使用独立 bundle identifier `local.mycodex.adapters.launcher`。用户选择自己的 CLI 路径和已登录账号，配置中没有模型 Key。Gemini 在独立私有目录登录，子进程从该目录运行，清理环境中的 API Key 并使用 0077 umask；父进程 umask 在失败时也恢复。

Claude SDK 固定为 `0.3.312` 并包含完整 lockfile；由使用者安装，不复制维护者的依赖缓存或认证。包内包含已编译模块，不要求使用者安装 TypeScript。用户仍需自行安装 Node 与 CLI，可选图标构建需要 Apple Command Line Tools。

## RC.2：根据真实用户反馈修正配置边界

用户报告能看到 Claude 模型菜单，但指出候选默认展示许多实际上不可用的模型；这只确认菜单可见，没有确认发送、审批、取消或冷恢复通过。原生路径已由用户明确选择：沿用官方 Codex 现有账号、Provider 和模型设置。

修正根因：旧向导强制接入一个外部 CLI；Claude 将服务端全部 `/models` 条目替换 CLI 候选；元数据发现没有与实际推理分开。RC.2 允许空网关目录与原生配置，外部连接默认 `enabledModels: []`，不加载未启用连接的 SDK。候选模型必须由用户主动选择、明确同意一次短请求并通过后才加入白名单；运行时拒绝白名单外的模型。

验证超时后禁止晚到的发现结果继续发推理；失败与并发配置变化不启用模型。Claude 短请求禁用工具、项目设置和会话持久化。服务端目录仅用于与 CLI 支持项求交，保留用户自己明确配置的自定义 ID；不把其他服务模型混入 Claude 菜单。

Gemini CLI 的个人 Google 登录服务已变更，RC.1 的登录承诺撤回，不再提供 Login-Gemini 入口。Google 模型可通过用户自己已有的 Antigravity ACP 1.4.4 连接候选路径；它还没有本候选的真实桌面验收证据，不能据元数据成功宣布稳定。

发布目标按用户最新指示为 `funkdog/ccodex-release`。RC.1 安装副本保留原样；不对正在使用的候选或日常开发目录热修。RC.2 另行冻结与验收，实际结果应绑定新的载荷摘要。


RC.2 自动验证：精简门禁 256/256 通过，零失败、取消和跳过，约 23 秒；新增原生空目录路由回归所在文件 29/29 通过（与门禁重叠，不相加）。217 个 ESM 模块、507 条相对导入校验通过。最终解压复验确认 470 项摘要、五个命令语法、无 SDK 的原生默认配置、真实私有空网关的准备/连接/退出、合成 CLI 候选与未启用状态，以及 Swift 图标编译和签名；没有自动操作桌面或调用真实模型。

## RC.3：同步“澄清待解决问题”中的桌面修复

来源：本轮用户指定的“澄清待解决问题”桌面修复聊天。该聊天的工作目录是本机开发 checkout；与精简 worktree 同在 `70e5964`，改动尚未提交，因此本次是按文件快照同步相关源码，而不是拉取到新的远程 Git 提交。原开发目录、日常会话与冻结的 RC.1 / RC.2 安装副本保持原样。

同步内容：紧凑的引擎/模型设置弹层；新聊天创建前选择引擎；已有聊天锁定引擎与来源，只切换兼容模型；原生 Codex 保留客户端自身的标准/快速模式动作和确认；修复缺少 `text_elements` 的新旧 CLI 历史投影。旧记录只在返回界面时补默认数组，不覆盖原存档。模型/速度切换失败、超时或上下文变化时不自动重试，也不替换已提交的模型。

精简渠道保留 RC.2 的原生优先配置与 `enabledModels` 限制，不接入来源/Key 管理、跨运行时历史迁移或 Squad 服务。新选择器在此渠道没有这些 RPC 入口。另修正移植时发现的原生模型命名问题：只有保留的 `mycodex/` 前缀表示网关引擎；原生 Provider 的 `provider/model` 名称不应被误归为 CLI。

验证先运行移入的上游回归：缺少快速模式导出、以及两条历史读取用例失败，随后同步实现使核心定向用例 51/51 通过。额外原生斜杠模型归属用例也先复现失败，再修正。新的真实浏览器夹具使用合成页面，不能替代客户端手动点击；此前聊天提供的进程就绪结果也不能证明本候选已经完成真实桌面验收。
