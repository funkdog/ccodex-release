# RC.3 之后的 Chat Completions 桥接修复

日期：2026-11-13（Asia/Shanghai）。本次按用户指定的开发聊天同步源码，并保留多 CLI 精简版的功能边界。来源聊天标题虽然提到 Squad，实际落地的是协议桥接修复；本次没有启用 Squad、工作台、模型来源管理或跨引擎历史迁移。

## 行为变化

- Desktop 附加的具名 `agent` 上下文在没有匹配模型调用时，作为带来源说明的参考数据传递，不伪造工具调用；真实工具结果、原生推理与压缩状态保持原语义。
- Chat Completions 保留工具命名空间、自定义工具原始输入、延迟工具发现以及工具返回的图片。Google Provider 的显式工具选择使用同一套转换后的名称。
- 对本地 Schema 引用和 nullable 属性进行兼容转换。无法直接表达的根联合或开放必填字段使用可逆的 JSON 字符串包装，返回时恢复原参数；格式错误明确失败。
- 当流式工具参数早于工具名到达时，按工具索引缓冲，识别名称后再发布，避免丢失命名空间或重复参数。
- Chat 路径不能承载的 `previous_response_id`、压缩项、输出项引用和文件附件返回 `400 unsupported_input`，避免静默丢弃输入。原生 Responses 路径不受此限制。
- 上游因长度或内容过滤终止时，返回 `incomplete` 并记录实际原因，不把部分工具调用标为完成。Chat 模型目录及提示词不再宣称具备仅 Responses 支持的传输、推理摘要和输出通道。

实现位于 `bridge/catalog.mjs`、`bridge/request-sanitize.mjs`、`bridge/translate.mjs`、`bridge/server.mjs` 与 `gateway/google-*.mts`。对应回归加入 `npm run test:adapters`；没有更改登录方式、用户配置、原生核心或补丁链。

原生 CLI 用例连接本地合成上游，并使用独立临时 profile；浏览器用例也使用合成页面。它们不证明真实账号、云端模型或桌面交互验收已经通过。
