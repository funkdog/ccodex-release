## 1. 需求演进脉络：四阶段迭代全景

### 阶段一：从视觉降噪与“去按钮化”切入
- **初始诉求**：旧版工作台视觉粗糙，小队之外的多个未成型 Tab 造成干扰，左侧会话栏缺乏小队分组/徽标感知。
- **初步共识**：砍掉未独立设计的冗余 Tab；去除工作台上的手动派单、扶正等操作按钮——日常调度全部在主聊天流中自然语言沟通完成，工作台只承担高信噪比的态势与成果呈现（期间调研对比了 Grok Bots 等多智能体界面形态）。

### 阶段二：V1 首次完整团队协作与结构性痛点暴露
使用 V1 机制跑完首轮改版后，虽然产出了代码，但深度复盘暴露出靠局部修补无法根治的四大摩擦：
1. **子会话认知税过重**：向子会话注入了大量本不该由执行者承担的协作引导提示词与回执协议，既挤占上下文又容易失真。
2. **生命周期与交付无物理兜底**：部分成员卡死、中途断流或漏写回执时，系统既无可靠的物理状态收口，也无法自动恢复或诚实暴露现场。
3. **共享黑板退化为流水账**：原本期望作为结构化共识黑板的 `ISSUE.md`，在多角色自由追加下迅速膨胀为无人收敛的过程日志。
4. **主会话调度心智内耗**：主会话消耗大量思考与轮次在“怎么催队友、怎么对齐状态”上，整体协作摩擦高于单会话直接推进。

### 阶段三：第一性原理重构（对标 `troupe`、Subagent 边界与社区共识）
拒绝用硬编码规则给 V1 打补丁，跳出既有实现细节，结合跨会话人肉同步的真实痛点（多会话切换、代码构建与探索、多模态创意协作等）以及 `troupe` 架构与社区多智能体工程铁律重新设计：
- 确立 `0034` Squad V2 架构基线，彻底移除预设常备角色（如 `supervisor`）。
- 拆分为协议清障（`role-protocol`）、状态与工作树内核（`role-kernel`）、原生分屏 Studio 与内嵌卡片（`role-studio`，含视觉原型先拍板 Gate）三路无交集并行实施，再由零历史包袱的 `clean-verifier` 独立终审，修复 `F1–F8` 对抗问题后合入主线并完成宿主兼容与 V1 残留清理（`49e1c06`）。

### 阶段四：用 Squad V2 自举打磨 Squad V2（`OPT-1` 至 `OPT-6`）
真机重启跑通 V2 闭环后，直接在主会话拉起持久隔离槽位 `fixer`，围绕在线实测体感连续完成 6 轮体验与协议优化，合入主工作区（`560b690`，59/59 专项回归与发布门禁全绿）并完成重启验收。

## 2. 核心讨论与架构决策（Why & Trade-offs）

### 决策 1：既然有了 Subagent，为什么还需要协作小队？
- **核心辨析**：`troupe` 与内置 Subagent 都是极其克制的 `1 Orchestrator + N Workers` 委派模型，Worker 不感知协作成本、只做确定性交付；但纯 Subagent 是黑盒、一次性、用完即焚的调用，牺牲了跨轮领域记忆、独立过程可观测性以及人类在必要时直接切入接管的能力。
- **我们的取舍**：采纳 `1 主会话 + N 角色槽位` 的星型控制（剥离 Worker 侧全部 `mycodex.squad_*` 工具，零协作噪音），但底层绑定**真实持久的原生/CLI 会话**。子会话默认在侧边栏隐藏防打扰，同时保留完整会话现场，支持跨轮复用（`stateful`）与按需一键扶正（`promote`）供人类深聊微调。

### 决策 2：上下文连续性与物理空间的正交双轴模型
- **连续性轴（`stateful` vs `clean`）**：
  - `stateful` 用于模块持续迭代、多轮修复或设计演进，保留领域上下文；
  - `clean` 用于代码审查、验收挑刺与对抗测试，每次派发强制新建空白会话，且仅投影客观验收判据与产物/Diff 引用（隔离主会话意图与实现推理），从根源杜绝路径偏见与上下文退化。
- **空间轴（`shared` vs `worktree`）**：
  - `shared`（默认）零拷贝共享当前目录，适配只读调研、方案推演与非代码协作；
  - `worktree` 在多路并行改码时启用，自动维护小队集成分支 `squad/<id>` 与槽位独立分支 `role/<id>/<slot>`，并在合入前硬性拦截脏工作树与 `outsideTouches` 越界改动。

### 决策 3：单写者结构化共享黑板 `STATE`（终结流水账）
- **核心规则**：废弃多写者追加式 `ISSUE.md`。共享状态收敛为带 `expectedRevision` 乐观并发锁的结构化 `STATE`（意图、不变量、公共契约、验收判据、动态任务图、阻塞项与 Gate），**写入权仅授予主会话与人类 Gate 批复**，物化生成只读 `STATE.md`。
- **隐性决策显性化**：Worker 无需维护全局黑板，只需在私有 `.mycodex/result.md` 中交付结果，并强制填写 `Assumptions & Trade-offs`，把执行中擅自做的边界假设暴露给主会话与人类审阅。

### 决策 4：Gateway 物理确定性与主会话业务语义的职责切分
- **代码管确定性事实**：Gateway 内核只做客观状态监控与物理守卫——包括追踪原生子会话内部是否仍有活跃 subagent（防止父回合结束但后台子代理仍在跑的假静止）、校验 Git 写边界、在 Worker 漏写 `result.md` 时自动合成物理增量快照，以及在主会话空闲时按边沿触发合并投递 `[Squad Notice]`。
- **模型管业务推进**：**物理静止（`quiescent`）不等于业务验收完成**。收到通知后是静默继续、重派返工、合入集成分支还是开启 Gate 请人类拍板，完全由主会话根据上下文语义自主判断，避免硬编码状态机锁死协作灵活性。

### 决策 5：面向高信噪比与防注意力涣散（Anti-ADHD）的双通道产品设计
- **核心痛点**：人与多 Agent 协作最大的摩擦，一是信息过载导致抓不住需要人拍板的共识、分歧与隐性取舍（沦为“许愿盲盒”），二是频繁被细碎过程打断注意力。
- **界面分工**：放弃局促的 360px 侧边抽屉，采用 **“主对话轻量内嵌回执卡（Inline Card）+ 右侧 Codex 原生分屏 Studio”** 双通道：
  - **主对话内嵌卡**：只在立项对齐（Blueprint）、门禁裁决（Gate）或阶段收束（Convergence）时按需呈现，支持卡片点击与聊天打字双通道同源批复。
  - **右侧原生分屏 Studio**：平时安静驻留，仅在需要人工介入时置顶显示 `Needs You`；支持查看全局 `STATE`、槽位隐性假设及原位展开文件 Diff，无需频繁跳转会话。

## 4. 已知边界与后续备忘

1. **冷启动历史子会话 `notLoaded` 映射**：真机重启验收观察到，客户端重启后尚未被唤醒进内存的历史原生子会话，`thread/read` 会返回 `status.type = "notLoaded"`（磁盘冷休眠态）。当前 `squad-v2-kernel.mts` 仅将 `idle / completed` 映射为 `quiescent`，其余兜底归入 `waiting`，导致历史槽位（含已 `closed` 小队）在客户端冷启动后被误标为 `waiting (notLoaded)` 并出现在 `Needs You` 中。下轮可在状态映射中将无待决轮次的 `notLoaded`（或已 `closed` 小队槽位）收敛为冷态静止。
2. **单写者模型的演进克制**：当前坚持由主会话单写者维护 `STATE`，在日常多模块开发与审查闭环中心智负担最低、状态最干净。在未真实遇到超大规模并发使主会话成为吞吐瓶颈前，不提前引入多写者合并或复杂自动工作流引擎。
