## 交付规则

- 每一步独立可评审；先解决启动契约，再实现引擎，不先批量移动旧文件。
- 缺省启动行为保持旧模式；不升级 `VERSION` 来表示设计进度。
- 文档改动只检查文档。本轮按用户明确的 Mac 本机范围执行，测试经既有 shell 调度器运行；不为本机验收安装 PowerShell、准备 Windows runner 或等待匹配的全平台发行产物。根目录 [AGENTS.md](../../AGENTS.md) 的正式跨平台发布流程留待相应发行任务执行。
- 自动化只使用临时隔离配置和合成会话；真实登录、推理与 Desktop 操作另列证据，不用模拟测试冒充。
- 需要外部先决条件时记录具体缺口，不伪造平台通过、模型可用或发行完成。
- 只创建承载真实行为的模块；首版不引入插件 SDK、独立控制服务、ORM、完整事件日志或通用服务容器。具体结构和延后条件见 ADR 3.3—3.4。
- 沿用原仓库职责划分，不建立 `mycodex/` 源码包。Desktop 改造落在 `bridge/desktop-*`，协议后端新增 `gateway/`，测试和发布继续使用原路径；不混入全仓目录搬迁。

## R0：证明真实 Desktop 可接入独立后端

产物是兼容性记录和最小协议验证，不是完整网关。

2026-10-28 结果：Desktop `26.1023.50603` 的原生模型选择、历史、输入和确定性回复显示通过；发现同一实例三个初始化连接及公开 schema 之外的发送接口。已选择薄 stdio 前端连接实例私有网关。首次欢迎流程通过仅限该版本的隔离配置跳过；不是未登录完整产品体验的验收。9 项定向测试通过，真实 CLI、持久化、审批、取消与发行尚未验收。

1. 记录目标 Desktop 版本、资源摘要、官方 CLI 版本和独立用户目录。
2. 在显式启动的隔离实例验证 `CODEX_CLI_PATH` 或该版本实际支持的接入点；从进程和握手两侧确认最终连接目标。
3. 记录 argv、启动/重启/daemon 子命令和初始化后请求清单。只记录协议形状及必要元数据，去掉 token、用户正文和私人路径。
4. 使用确定性协议桩验证一条合成会话的显示，不调用模型；验证无 Copilot API bridge、无 Copilot 账户也能进入目标引擎选择流程。
5. 若界面仍要求官方宿主服务，列明最小方法与身份呈现方案；不能返回虚假“已登录”绕过界面。
6. 判定直接 stdio 是否足够，是否需要多连接共享后端或 Desktop 重启后继续任务。只有真实需求成立才采用 shim + 私有 daemon，并在进入 R2 前确定相应生命周期与连接测试。

验收：能证明消息进入独立后端；原应用实例、默认 daemon/socket 和用户历史不受替换。不能证明这一点时停止扩大功能实现，明确不支持的版本/平台。

## R1：拆分模式启动与配置

目标：模式分流发生在桥接登录和准备动作之前。

| 现有文件/入口 | 需要的改造 |
|---|---|
| `release/desktop-entry.mjs` | 先解析模式；仅旧模式执行原有 GitHub 登录流程 |
| `release/launch.mjs` | 按模式准备 profile、端口、认证与服务；网关不经过 `ensureReleasePort`/Copilot 登录分支 |
| `developer/launch.mjs` | 与发布版共用模式解析；网关启动不得先调用 `currentPort()`/`ensureBridge()`，开发环境也不能预置旧模式配置作为新模式输入 |
| `platforms/macos/bin/codex-copilot-desktop`、Linux 对应入口 | 汇入统一模式启动入口，消费自有参数后才传给 Desktop |
| `bridge/desktop-launch.mjs` | 原地保留公共生命周期，注入后端差异；两种模式共用此实现，不新增另一套启动器 |
| 新增 `bridge/desktop-mode.mjs`、`desktop-backends/` | 统一配置解析及两种准备函数；选定后端才导入，避免旧账户/profile 顶层初始化污染网关模式 |
| `bridge/desktop-runtime.mjs`、`release/environment.mjs` | 通用环境清理与模式 envPatch 分开；避免把覆盖变量传给 CLI 工具后代造成递归 |
| `tools/gen-config.mjs`、`release/prepare-profile.mjs` | 保留旧 Provider 配置函数；新增网关专用配置，不覆盖旧模型设置 |
| `bridge/desktop-instance.mjs` | 新实例记录不强制桥接端口；验证模式、配置代次和进程生命周期 |
| `release/desktop-preflight.mjs`、`desktop-startup.mjs`、`desktop-preparation.mjs` | 按模式检查真正后端；不能用旧 SQLite 或日志签名代表网关已就绪 |

顺序：在 `bridge/desktop-mode.mjs` 加配置解析，在 `bridge/desktop-backends/` 加模式准备函数，再利用既有 `launchDesktop` 注入点接入各平台。启动计划只保留普通字段、后端检查与归属清理回调，不建设通用服务生命周期调度器。通用模块虽沿用 `bridge/` 位置，依赖上仍不得绑定 Copilot 全局状态。

验收：

- 缺失新配置时，原有启动测试和行为不变。
- 网关模式的测试桩对旧 bridge 启动、Copilot 认证、Provider 配置写入设为禁止调用，并验证调用次数为零。
- 无效模式、冲突实例、不存在 CLI、损坏配置产生明确错误，不启动另一模式。
- 两种模式同时运行，配置、连接、关闭与重启互不串用。
- 配置样例转为正式 schema 后，解析器、文档和样例一起更新。

## R2：独立网关核心与协议契约

目标：通过确定性引擎桩和协议客户端覆盖生命周期；不依赖 CDP 或付费推理。

实现：R0 选定的薄 stdio 前端与实例私有 IPC、握手、方法处理表、静态引擎工厂 Map、模型目录、会话元数据和必要投影、连接与反向审批映射。公开协议之外还需适配当前 Desktop 的 `getAuthStatus`、`turn/addUserMessage`；历史覆盖 `thread/turns/list`、`thread/items/list`。宿主能力只实现 R0 证实需要的方法，不先建 HostServices 平台；未知方法默认拒绝，禁止泛化转发。

源码落在 `gateway/`，适配器落在 `gateway/engines/`；测试按仓库现有方式放在 `tests/gateway-*.mjs`。只使用当前打包方式，不给该目录新增独立包发布、锁文件和 CI 体系。`bridge/desktop-backends/` 负责接入它，网关不能导入客户端生命周期来反向启动页面。

首版只持久化关键元数据和必要投影，网关是唯一写者。对照现有原子 JSON 与目标运行时可用的嵌入式 SQLite，记录一致性、恢复、规模和实现成本后选择，不为少一个依赖而手写复杂事务。验证损坏状态、写入中崩溃、两个网关争抢实例和恢复时结果未知。历史从 CLI 读回或保存已完成投影，不落盘每个 token。协议 schema 取自目标 CLI，不以最新文档替代固定版本。

验收重点：

- 两连接使用同一个请求 ID、并发工具审批、断线重连时不串响应。
- 事件有序，终结恰好一次；取消未确认时不提前标记完成。
- 新建/执行中崩溃、CLI 已执行但结果未持久化时不自动重发。
- 请求未知引擎、错误权限策略、不支持的输入类型时无任务副作用。
- 目录分页稳定；恢复和归档按持久化归属执行，不使用当前默认值。
- 网关输出通过目标 schema；stdin/stdout 只有协议消息，日志写 stderr 或实例日志。
- 关闭所有增强后协议闭环通过；宿主辅助进程故障不会连带结束其他引擎任务。
- 模块边界检查确保 gateway 不导入 CDP/React、引擎不导入旧 API bridge；不以新增一套框架作为通过条件。

## R3：接入真实 CLI 引擎

先实现 Claude Code 的一个完整纵向闭环，再按相同契约实现 Copilot CLI；两者均通过才宣称首版多 CLI 可用。

| 场景 | Claude Code | GitHub Copilot CLI |
|---|---|---|
| 版本、认证、模型目录 | 适配目标 CLI/SDK 的真实接口 | 使用 CLI/SDK 的真实目录，账户不可用时明确报告 |
| 新会话和正文流 | 原生会话 ID 与网关 ID 绑定 | 同样绑定，不经过现有 `bridge/server.mjs` 推理 |
| 工具与文件修改 | 映射真实事件和结果 | 映射真实事件和结果 |
| 审批与用户提问 | 只采用实际支持的回调/协议 | 验证其审批语义，禁止默认批准 |
| 恢复和取消 | 验证进程重启及同一会话恢复 | 验证模型选择保留及取消结果 |
| Gemini | 不适用 | 从账户可用目录选择；不写死“Gemini 4”或承诺可用 |

真实验收至少包含：一个文本任务、一个受控文件修改、一次审批拒绝、一次中断、一次重启恢复、一次认证失败。测试记录模型来源及实际引擎，不把 SDK 握手成功算作任务完成。

检查不存在网关自动标题/摘要/故障转发的 Codex 推理调用。宿主服务使用方法白名单；选择第三方引擎时不得发出隐式 Codex `turn/start`。

## R4：复用增强宿主与用户入口

优先原地复用 `bridge/desktop-cdp.mjs` 的传输，将其中硬编码的回复事件白名单改为由调用方提供并校验；不删去边界校验。在 `bridge/desktop-patch.mjs` 拆开业务处理函数和静态组件数组，新增组件放在 `bridge/desktop-components/`。现有账户/会话/更新 UI 在旧模式保持可用，不为支持网关而先重写或批量迁移它们。

首个组件是 CLI 新会话选择器，使用实际模型目录及工作目录创建空线程，再导航到原生会话页；不写原生默认模型。这样避免原生模型选择器的配置写入副作用。不另建统一会话列表或账户/额度中心；旧账户组件暂不迁移。模型 Context 等控件仅对实际支持的引擎显示。

首版按组件需要选择一种展示入口；后续验证可行后可再增加官方插件展示。需要原页面插入的位置使用版本化 CDP 适配。普通函数注入用于进程内调用；跨进程时复用 binding/私有 IPC，按实际需求增加受限消息，不另起通用管理服务。

验收：

- 当前模式、下次默认模式和当前会话引擎均可区分；切换不影响正在运行的任务。
- 一个不依赖聊天的 DIY 组件可在两种模式复用同一个业务实现。
- 组件卸载/反复注入没有重复事件、泄漏和自触发观察循环。
- React/DOM 探测失败时只停用该增强；网关与 CLI 会话继续受控运行。
- 私人 token 不进入 renderer；任意组件不能通过控制接口执行未经注册的 shell 命令。

## R5：macOS 本地交付、更新与回滚

将新增 `gateway/` 纳入现有安装器/开发同步、源码摘要和兼容性检查；重点核对 `bridge/desktop-extension-files.mjs`、`tools/Check-PackageModules.mjs`、`tools/export-bundle.mjs` 及各平台实际 stage 清单。新的 `bridge/desktop-*` 子目录也要确认被递归包含。不能只让开发目录可用，离线包漏文件。

目录留在原位置不意味着发布脚本自然支持新后端。检查旧模式和网关模式实际需要的资源，避免新增网关后仍无条件拉起或要求旧 Copilot API bridge；沿用一套工具链并分别验证依赖闭包，不为个人增强另建发布系统。

为 Desktop、网关、CLI/SDK、组件边界建立组合验收记录，沿用现有更新流程，不为各模块建立独立更新服务。候选更新使用临时实例和合成会话；状态迁移可恢复后再推广，不修改正在执行的实例。

本轮通过既有 shell 调度器完成 macOS 的依赖检查、测试及本地接入验收，不要求先生成全平台安装包。保留已有发行清单改动，正式离线打包和跨平台发布另行安排。未验证的平台保持未支持；不能从 macOS 验证推导 Windows DLL 或 Linux 路径正确。

## 完成定义

只有以下条件同时满足，才能将“网关模式”列为本机 macOS 可用功能；正式发布单独验收：

1. 用户能实际选择两种模式；旧模式回归通过。
2. 真实 Desktop 连接独立网关，不依赖模型 API bridge。
3. Claude Code 与 Copilot CLI 各自完成会话、工具、审批、取消、恢复闭环。
4. 目标账户提供 Gemini 时能在 Copilot CLI 会话使用；目录缺失时不伪造选项。
5. 路由和 UI 不产生额外宿主模型推理；没有自动跨引擎重试。
6. 增强组件具有独立生命周期、版本适配和能力服务；网关可以脱离 CDP 验证。
7. macOS 本地接入、停用恢复、更新兼容及状态保护有证据。正式安装包和其他平台不作为本轮完成条件。

目前已完成设计、R0 探针、R1—R3 初始源码以及 R4 选择器/R5 本机准备。Copilot 已登录并有真实文本、恢复与权限操作证据；Claude 未登录，Gemini 不在当前目录。当前 ChatGPT 未重启或启用，页面共存、取消/提问、停用/更新仍待验证；不能称为完整多 CLI 可用或正式发布。
