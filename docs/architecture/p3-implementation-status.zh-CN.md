更新：2026-11-03（Asia/Shanghai）。规格：[ADR 0026](0026-spine-p3-review-design.zh-CN.md)。状态：**第二轮投递执行层源码及隔离验证完成；P3.0 的真实 Desktop 与工作依据接线验收仍未完成，尚未发布或加载到当前工作客户端。**

## 第二轮：持久处理与受控投递（2026-11-03）

- 新增 `ReactionStore` 和 `WorkDispatchService`。记录按对象分片、私有保存，采用 revision 冲突检查和既有 fsync/原子替换；先保存 `dispatching` 意图，再调用原生端口。相同工作项、来源变化与规范化动作只形成一个处理身份，Watch 或策略版本变化不能自动重做历史动作。
- 排队和原生实际接纳前分别核对服务端提供的 Brief/策略版本、负责会话、接管/暂停、资源版本及预算。异步资源检查后再次读取授权快照，确认还绑定同一完整策略。提交给模型的内容包含冻结的有效工作依据，并将外部内容明确作为待核实 JSON 资料；回到网关的最终确认绑定确切文本、工作区和目标。外部文本不能扩大网关派发权限。
- **产品默认自动派发仍关闭。** 权威工作依据和真实资源核对必须由服务端工作服务提供，JSON 配置、来源文本及 MCP 参数不能提供授权函数。当前 WorkItem/Brief 所有者尚未实现；本轮实际投递使用显式注入的隔离测试依据与合成资源校验。这不等于已完成真实 Git/工作树版本核验或产品授权入口。
- 原生前端复用自己的 app-server；投递前取得该前端的短时会话操作保留，并核对目标、账号、当前 cwd 和 idle 状态。原生用户请求按原顺序等待，不丢输入，不修改模型、推理或审批配置；忙碌时仍排队，不使用 `turn/steer`、resume、新会话或另一个原生运行时绕过检查。工作区协调只覆盖 MyCodex 自己的自动派发。
- 原生适配层保留有界的运行时回执缓存。`accepted` 绑定真实 turn ID，`settled` 只记录原生执行终态，不自动宣布业务验收。回执丢失先查询，未知结果保留待核对及资源保留，不自动重发；部分记录损坏保留原字节和诊断，暂停新的自动写入，既有会话路由继续可用。queued 可本地取消，已启动执行的原生取消尚未接入。
- 同一 generation/token 的网关连接断开后，原前端以退避方式重连，保留原 runtime ID 和回执；临时读取故障有 30 秒恢复窗口。token 轮换、原生运行时替换或不可核对的结果仍进入待核对。没有承诺原生严格一次执行：实测同一 `clientUserMessageId` 连续两次会启动两个不同 turn，因此 `requestIdempotency` 继续为 false。
- UI/MCP 增加处理记录的分页列表和读取，未开放原始投递、重试或授权工具。原生可选宿主模块改在初始化完成后后台加载，四秒的可选模块加载延迟不会阻断原生握手。

## 第一轮交付（2026-11-02）

- Gateway 在基础协议和引擎就绪后加载 Spine。Registry、kernel、各来源模块及宿主读取模块具有独立加载/初始化边界；状态接口报告各模块健康。模块方法在初始化成功后统一公布，并发初始化不能覆盖已有方法。无效雷达配置、不兼容 Spine schema、损坏的可选存储目录均保留原数据，既有 CLI 路由继续工作。
- 原生前端沿自己的现有 app-server 连接建立独立鉴权的反向只读通道。目标包含 host/account、原生 thread ID 与明确的 runtime 绑定；断线、账号变化、归属冲突或目标错误明确失败。UI、trace 与 native-host 三种通道不能互相冒用，前端不写 Spine 数据。
- UI 服务与 MCP 共用 `diy/host/status`、`diy/host/read`、`diy/host/result`。MCP 增加对应三个只读工具；状态和结果均从指定原生运行时回读，结果只包含目标 turn 的 Agent 正文。结果采用每页 8192 UTF-16 code units 的有界返回，不拆分代理对；查找限定最近 100 个 turn，超预算明确报不可取得。
- 能力表保留独立的 delivery、requestIdempotency、receiptLookup、safeDuringRun、openTarget 字段。本轮这些字段均为 false；结果读取在该 runtime 成功验证前也为 false。当前未提供发送、排队、创建会话或草稿插入接口。
- 新增可释放的后台活动计数，接入现有 idle 判断；重复释放安全，shutdown 不等待活动租约。这为后续 Watch 调度提供寿命接口，本轮尚无 Watch 调度器。

原生线程的历史读取使用官方分页接口。隔离验证先复现 `thread/read(includeTurns=true)` 返回 `list_turns is not supported yet`，随后改用 `thread/turns/list`；没有通过 resume、重开运行时或伪造缓存结果规避该限制。[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)说明了新历史存储的分页读取方式。
